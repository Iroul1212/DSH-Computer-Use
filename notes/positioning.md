# 让这个插件更"吸引人"：现状、候选能力与取舍

> 结论先说：我们已经在**坐标闭环 / 失败关闭的安全 / 零依赖 / 可测性 / token 经济**五点上有明确优势；
> 真正缺的是**观测能力**（尤其 OCR）和**自适应性**（做完动作自己验证、自己积累经验）。
> 下面按"收益 ÷ 成本"排序，P0 是这轮已经在做的。

## 0. 已经具备的差异化（对外的卖点）

| 卖点 | 一句话证据 |
|---|---|
| 坐标不点偏 | 截图压到 ≤600000px 落在宿主请求预算内，`scale` 在代码内反算并在文本信封回显；竞品把缩放系数丢给模型自己除 |
| 看不见就别动 | 窗口漂移/进程重启/守卫死亡/宿主死亡 → 全部 fail closed，只读动作仍可用 |
| 依赖为零 | 不 import 任何 `@deepseek-ai/*`，跨 0.1.x / 0.2.x 版本线都不炸 |
| 可被验证 | 5 个测试套件、40+ 断言，含复用宿主自己的 JSON Schema validator |
| 省 token | 36 action 压进 5 个工具、工具定义 ~10.2K 字符（同类 20.2K）；截图只回附件引用 |
| 文本模型可用 | 截图自带 UIA 大纲 + App 技能配方，不依赖视觉也能干活 |

## 1. 候选能力（按性价比排序）

| # | 能力 | 收益 | 成本 | 依赖/风险 |
|---|---|---|---|---|
| **1** | **OCR**（Windows.Media.Ocr，`ocr` 命令 + 截图可选带 OCR 文本） | ★★★★★ 纯文本模型也能"看懂"画布/游戏/远程桌面/图片里的字；并且让 `waitFor text`、`find by text`、`click text` 成为可能 | 中（3~4 天） | **路径已验证**：`Add-Type` 加载不了 winmd，要用 `csc.exe` 引 4 个 winmd 现场编译并缓存 DLL；async 用 `TaskCompletionSource` + `op.Completed` 桥；返回**词级 BoundingRect**，除以截图 scale 再加窗口原点即物理坐标。可直接照抄 `_reference\\_gh\\shinji00222_dsh-windows-computer-use\\upstream\\scripts\\windows-uia.ps1:884-978` |
| **2** | **动作后自校验**（截图变化比例/区域；"点了但没变"直接告诉模型） | ★★★★★ 终结"点了没反应→重试→再重试"的死循环，是 agent 自主闭环的地基 | 低 | 宿主侧像素比对（或先做 base64 相同判定降级版） |
| **3** | **坐标网格叠加**（`grid`/`mark`/`dim`） | ★★★★ 视觉模型读坐标的准确率大幅提升；`mark` 还能当"我刚才点这里"的自我确认 | 低 | 服务端在缩放后的图上画 |
| **4** | **`waitFor`**（stable / window / element / text） | ★★★★ 把 `sleep` 变确定性等待，UI 慢的时候成功率立涨 | 中 | text 依赖 OCR；element 用 UIA；stable 用像素比对 |
| **5** | **自我改进技能**（`app_skill save/append/remove`） | ★★★★ 成功一次就写下配方，下次直接命中；形成"越用越快"的产品叙事 | 低 | 写盘要过 mutating 安全门 + 4000 字上限 |
| **6** | **按描述找控件 + 候选排序**（模糊匹配 UIA 树，返回 top-3 + 标注截图） | ★★★★ 中文 App 控件名杂乱时，"找到'保存'那个按钮"比坐标可靠 | 中 | 纯 JS 打分即可，无需新依赖 |
| **7** | **审批预览图**（把 `mark`/`dim` 后的图交给用户确认） | ★★★ 让"人盯着 agent 操作"变得可交互、可审计 | 低 | 复用截图装饰 + DSH 审批（注意 `never` 策略下恒拒） |
| **8** | **动作审计与回放**（每步 before/after 截图引用 + 动作参数） | ★★★ 排障、演示、问责；也是"agent 操作日志"卖点 | 中 | 会话事件 or 本地 jsonl |
| **9** | **敏感区域脱敏**（对配置的窗口/矩形打码后再编码） | ★★★ 截图要上传给模型，这条是真实顾虑；也是企业采纳的门槛 | 低 | 在宿主里对位图做高斯/纯黑填充 |
| **10** | **网页优先走 DOM**（可选挂 CDP/浏览器插件后端） | ★★★ 网页里 DOM 比像素稳得多 | 高 | 需要另一个后端；建议"能 DOM 就 DOM，否则退回像素" |
| **11** | **npm 发布 + `dsh plugin add dsh-computer-use` 一行装** | ★★★ 分发决定采用率 | 低 | 只是发布流程与 README 首屏 |
| **12** | **DSH web 设置页**（开关/审批/技能卡片） | ★★ 好看、可发现性高 | 高 | 需 react + `dsh.client` 契约 |
| 13 | 组合动作宏（把多步操作记成一个 `macro`） | ★★ | 中 | 与技能库天然合并，不必单独做 |
| 14 | 多屏合成截图 + 每屏独立 overlay | ★★ | 低 | 已有 `screens` 基础 |

## 2. 推荐路线

**P0（这一轮）**：1 OCR、2 自校验、3 网格/标记、4 waitFor、5 自我改进技能。
前四个都是"让 agent 更能自己看见自己干成了没有"，第五个是"越用越快"，四件合起来就是一句可宣传的话：
> **看得见（OCR+网格）、知道自己有没有做成（自校验+waitFor）、还会自己记笔记（技能库）。**

**P1**：6 按描述找控件、7 审批预览、9 脱敏、11 npm 发布。
**P2**：8 审计回放、10 DOM 后端、12 web UI。

## 3. 明确不做

- **不做 C#/koffi 原生助手**：引入编译与原生依赖故障面，收益只是延迟；我们 PowerShell 常驻已够快（截图 ~150ms、cursor 0.42ms）。
- **不做 25 个细粒度工具**：工具定义体积翻倍、弱模型选择困难、破坏请求 shape 稳定性。
- **不做"按应用自动授权"**：竞品在全权会话下退化成"模型点名即授权"，我们不重复这个坑。

## 4. 怎么验证"更吸引人"（而不是自嗨）

1. **任务成功率对照**：固定 10 个任务（记事本写字、Excel 录入并另存、Chrome 搜索并复制结果、资源管理器新建文件夹并重命名…），分别跑"裸坐标"与"UIA+技能"，记录步数/耗时/失败原因。
2. **失败自愈率**：故意在流程中间制造一次"窗口被挪走/弹窗出现"，看 `TARGET_WINDOW_MOVED` / `waitFor` 是否让 agent 自恢复。
3. **token 账本**：同一任务的开销（工具定义 + 截图 + 文本信封）与竞品比。
4. **一键 demo**：`node test/demo.mjs` 跑一个 30 秒脚本，产出 GIF/截图序列 —— 这比 README 里写十个特性都管用。
